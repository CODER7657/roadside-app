Source of truth: PLAN.md §6 (Lane) · §10 (screens)

Every screen, on Lane templates.

These are mid-fidelity wireframes for all three apps: 10 common screens, 20 customer frames, 9 mechanic screens and 6 admin screens. Grey shows structure, the amber gradient marks the one primary action, and colour always means a booking status. Each frame names its template and key components, so every member builds the same screen the same way.

How to read a frame

  • ID: C = common, U = customer, M = mechanic, A = admin
  • Template: one of the 6 in PLAN §6.13
  • Grey bars = real text/data goes here
  • Dashed boxes = image or illustration slot

Rules to keep

  • One primary button per screen, in the bottom dock
  • Critical buttons 64 dp; everything ≥ 48 dp
  • Every error / empty state has an action
